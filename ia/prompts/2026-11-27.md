Cierra la historia 3 contra el enunciado y valida que se cumpla todo el requerimiento. El login es `GET /auth/login?username=&password=` con el header `X-Jwt-Secret`. La API firma y verifica el JWT HS256 con el secreto que manda el front (`NEXT_PUBLIC_JWT_SECRET`, el mismo valor que `JWT_SECRET`, sin relleno). El token no vence, lleva el rol y queda en `localStorage`. El 401 distingue «El usuario no existe» y «La contraseña es incorrecta». Productos y categorías sin token o con token inválido responden 401. El manager que crea, edita o elimina recibe 403. Cerrar sesión descarta el token y vuelve al login. La API acepta cualquier origen. Todas las peticiones del front incluyen `X-Jwt-Secret`. En los GET de consulta el token va en `Authorization: Bearer`. En crear, editar y eliminar va en el campo `token` del body. El borrado es `GET /products/:id/delete`: por ser GET también lleva `Authorization`, y por ser eliminar también manda el campo `token`.

El detalle está en [../planes/plan-hu03.md](../planes/plan-hu03.md).
